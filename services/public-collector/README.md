# Public collector sidecar

The Python desktop backend owns this Node child and communicates over bounded NDJSON on private stdio. The process does not bind a socket. Its only data methods accept the five stable operation IDs in `src/contracts.ts`; callers cannot submit a site name, URL, operation name, or untyped input field. Calls use the learned operation through api-anything's tier-1 path. They never import the owner's browser cookies or session. The Python client requires the app-owned collector data directory and starts a child with a maximum 15-minute lifetime; each request is bounded. It declares `LeviathanPublicCollector/1.0` as the User-Agent for HTTP and isolated Chrome requests.

The upstream source is vendored at `vendor/api-anything` from commit `fe5cca70fe145634e49a1c9ba1f3e8250b291bea`, including its MIT license. The shipped runtime is built from the explicit TypeScript runtime graph; MCP, Express, CLI, login, and cookie-import modules are not packaged. `patches/api-anything-runtime.patch` is one regenerated unified diff from that pristine upstream revision, including dependency and lockfile pruning, the runtime TypeScript include list, and maintained source changes. Run `node scripts/regenerate-vendor-patch.mjs` to regenerate it; the script verifies reverse application to the vendored state and clean application to the reconstructed pristine tree. The build applies the patch in both directions to verify it and pins it by SHA-256 `5409be5220c92fc6c6b2d5d6acc2ca819983a61f3204403ab5a58c175f0431cc`. The generated `runtime-manifest.json` records the source commit, patch hash, exact `playwright-core` 1.63.0 version, minimum Node version, and deterministic hash of the shipped runtime files. The dead `headlessUserAgent()` helper is removed from the patched source and output.

`templates/PINNED.json` is the repo-committed activation registry. No operations are currently pinned. Learn and repair create quarantined candidates in app data and never activate them. Each operation has a reviewed native-to-contract `mappingRecipe`, passed into `addOperation` and recorded with candidate and pin metadata together with its SHA-256. Fixture sanitation preserves recipe-consumed values byte-for-byte and redacts unconsumed personal data; per-operation tests prove sanitizer replay extracts the same value as the live native body. Fed and Senate entries require recorded real native bodies before a pin may be activated. The mapping tests run the built vendor extractor over recorded or explicitly labelled hand-built native bodies and validate each strict contract. A version serves only after its operation ID, version, template SHA-256, mapping recipe, allowed hosts, ToS review, fixture, freshness deadline, and review note are pinned through the writer, acceptance, review, and coordinator integration flow. Approval expires after 90 days; the separate 48-hour canary freshness deadline requires a passing canary before stale data can serve. Until then, calls return `TEMPLATE_UNPINNED` or abstain. Per-operation semantic checks validate required fields, value/date ranges, duplicate IDs, record counts, and operation-specific constraints; fixture schemas are checked before use. First-seen timestamps are write-once by source key plus content hash, with a monotonic ledger. Local raw-response replay uses a temporary home under the app data directory and bypasses network pacing. Call cadence is a persisted nonblocking gate: a call returns an unexpired last-good record or typed `RATE_LIMITED`/`NOT_DUE` immediately. Learn/repair use separate persisted polite spacing and 429 backoff.

The desktop client exposes typed `USER_ACTION_REQUIRED` notifications from the bounded stdout event stream. When a challenge is detected from structured status/signals, the sidecar opens the public challenge page in a visible Google Chrome window using an app-owned isolated profile, then notifies the user and waits up to 10 minutes for an explicit Done action and a passing semantic check. It never imports the owner's browser cookies, solves a challenge, calls solvers, or spoofs fingerprints. A failed window open returns `CHALLENGE_WINDOW_FAILED`; dismissal and timeout return `USER_ACTION_DECLINED` and `TIMEOUT`.

The official BLS ICS, BEA calendar data, and Census iCal/RSS calendar export belong in the official-source adapter lane. Treasury auction announcements/results are available through the official Fiscal Data Auctions dataset/API. This sidecar keeps only gaps: Fed FOMC calendar, forward earnings, Senate eFD PTR, Cboe daily statistics, and CNN Fear & Greed. No live templates are bundled; until a source's template is learned, reviewed, and hash-pinned, its operation returns `TEMPLATE_UNPINNED`.

Sources classified `REVIEW` are approved only for internal single-user use. Every emitted response and record has `redistribution: false`; the app must not serve those records to other users pending licence review. CME FedWatch stays excluded because its terms prohibit automation; INTEL should derive the equivalent FOMC probability curves from licensed Databento ZQ data.

## macOS 11 Intel

The current Playwright requirements are macOS 14 or newer, so visible challenge handling and browser repair are unsupported on the owner's Big Sur host. Node 22 publishes a macOS Intel binary, but that listing does not establish compatibility with this specific Big Sur machine. `api_anything_templates.export_pinned_template()` exports only a template whose digest matches the committed pin and rejects cookie/session/auth material. `import_pinned_template()` verifies the committed pin and digest before installing it in the app data directory. The Python supervisor detects macOS 11.7, enters replay-only mode, forbids learn/repair/challenge windows, and allows only pinned tier-1 HTTP template calls. Direct Big Sur Node/Playwright launch remains unverified.

On Windows, apply restrictive ACLs to the committed activation registry with `scripts/secure-pinned-registry.ps1`. This limits file access to the current user, SYSTEM, and local Administrators; it is local tamper resistance, not a cryptographic signature. Source terms, reviewer, verdict, and `redistribution: false` are recorded in `templates/PINNED.json`.

The official docs currently list Windows 11+ and macOS 14+ for Playwright: <https://playwright.dev/docs/intro#system-requirements>. Node 22 archive: <https://nodejs.org/en/download/archive/v22>.
